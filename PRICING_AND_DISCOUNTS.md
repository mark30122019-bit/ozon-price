# Цены и скидки: как работает приложение

Этот документ описывает, какие цены использует скрипт и что происходит при скидках на Ozon (в том числе скидке площадки 50%).

---

## Какие две цены использует приложение

Скрипт работает с данными из Ozon Seller API (`/v5/product/info/prices`) и опирается на **два поля**:

| Поле в API | Что это | Зачем нужно |
|------------|---------|-------------|
| `price.price` | **Ваша базовая цена** в кабинете продавца | От неё считается новая цена и отправляется обратно в Ozon |
| `price_indexes.price_with_ozon_card` | **Цена для покупателя с Ozon Картой** | С ней сравнивается порог `TARGET_MARKET_PRICE` |

Код читает эти поля в файле `app/pricing.py`:

- `get_base_price()` → `price.price`
- `get_price_with_ozon_card()` → `price_indexes.price_with_ozon_card`

Приложение **не смотрит** на витрину Ozon напрямую. Оно не анализирует `old_price`, акции в личном кабинете и другие поля — только то, что вернул API.

---

## Логика пересчёта

Порог задаётся переменной `TARGET_MARKET_PRICE` (по умолчанию **1500 ₽**).  
Наценка к текущей витринной цене — `SITE_PRICE_MARKUP_PERCENT` (по умолчанию **5%**).

**Если** цена с Ozon Картой **ниже** порога:

```
целевая цена на сайте = цена с картой × (1 + SITE_PRICE_MARKUP_PERCENT / 100)
новая базовая цена   = текущая базовая цена + (целевая цена на сайте − цена с картой)
```

**Пример:** цена с картой = 1200 ₽, наценка 5% → цель на сайте = **1260 ₽** → базу поднимаем на **60 ₽**.

**Если** цена с картой **уже выше или равна** порогу — товар **не меняется**.

Формула находится в `app/pricing.py`, функции `calculate_desired_site_price()` и `calculate_new_base_price()`.

---

## Пример: скидка 50% на Ozon

Допустим:

- `TARGET_MARKET_PRICE` = **1500 ₽**
- ваша базовая цена (`price.price`) = **2000 ₽**
- покупатель с картой видит (`price_with_ozon_card`) = **1000 ₽** (из‑за скидки Ozon ~50%)

Расчёт:

| Шаг | Значение |
|-----|----------|
| Цена с картой | 1000 ₽ |
| Наценка 5% | 1000 × 1.05 = **1050 ₽** (цель на сайте) |
| Разница | 1050 − 1000 = **50 ₽** |
| Новая базовая цена | 2000 + 50 = **2050 ₽** |

Скрипт поднимет базовую цену на **50 ₽**, чтобы витринная цена выросла на 5% от текущей.  
Это **не** подъём ровно до порога 1500 ₽ — шаги небольшие, при повторных запусках цена может постепенно расти.

---

## Будет ли результат точно 1500 ₽?

**Не обязательно.** Возможны такие ситуации:

### Ozon пересчитает соинвест после вашего изменения

Вы подняли базу до 2500 ₽, но Ozon снова применил скидку ~50%.  
Покупатель может увидеть, например, **1250 ₽**, а не 1500 ₽.

При следующем запуске (например, через 10 минут) скрипт снова поднимет базу.  
Возможен **цикл**: подняли цену → Ozon изменил скидку → снова ниже порога → снова подняли.

### Лимиты Ozon

На один товар — примерно **10 обновлений цены в час**.  
При частом таймере и постоянных пересчётах соинвеста лимит может быть исчерпан.

### Поле `price_with_ozon_card` может отсутствовать

Если API не вернул это поле для товара — скрипт **пропускает** его и **не меняет** цену.  
В логах будет предупреждение: `нет price_with_ozon_card`.

## Типы скидок и поведение скрипта

### 1. Скидка Ozon (соинвест, СПП, скидка площадки)

**Это как раз тот случай, под который заточена формула:**  
если покупатель видит слишком дёшево из‑за скидки Ozon — скрипт поднимает вашу базовую цену.

Ограничения:

- нужно, чтобы API отдавал актуальную `price_with_ozon_card`;
- Ozon может динамически менять размер соинвеста;
- точное попадание в `TARGET_MARKET_PRICE` не гарантируется.

### 2. Ваша собственная скидка (вы сами снизили цену в кабинете)

Например, вы выставили `price = 1000` вместо 2000.

- `price.price` = 1000 (ваша цена уже со скидкой)
- если `price_with_ozon_card` тоже около 1000 → скрипт снова поднимет базу

Скрипт **не различает**, кто дал скидку — вы или Ozon.  
Он видит только: «покупатель с картой видит меньше порога → поднять базу».

### 3. Акция Ozon на товар (участие в промо)

Если товар участвует в акции Ozon и цена с картой временно падает:

- скрипт будет пытаться поднять базу **и во время акции**;
- после окончания акции цена для покупателя может стать выше порога — тогда скрипт перестанет трогать товар.

## Краткая шпаргалка

| Вопрос | Ответ |
|--------|--------|
| Какую цену сравниваем с порогом? | `price_indexes.price_with_ozon_card` |
| Какую цену меняем? | `price.price` (ваша базовая в кабинете) |
| Учитывает ли скидку 50% от Ozon? | Да, **если** API отдаёт актуальную `price_with_ozon_card` с учётом скидки |
| Всегда ли получится ровно `TARGET_MARKET_PRICE`? | **Нет** — соинвест, акции и лимиты API могут мешать |
| Что если поля нет в ответе API? | Товар пропускается, цена не меняется |

## Рекомендация перед боевым запуском

1. Создайте `.env` из `.env.example`.
2. Включите безопасный режим: `DRY_RUN=1`.
3. Запустите локально: `py -3 run_local.py`.
4. Проверьте в логах:
   - приходит ли `price_with_ozon_card` для ваших товаров;
   - какие базовые цены скрипт **хотел бы** выставить при текущих скидках Ozon.

Только после этого отключайте `DRY_RUN` или загружайте функцию в Yandex Cloud.

---

## Возможные доработки (по запросу)

- не трогать товары, участвующие в акциях Ozon;
- ограничить максимальный шаг повышения цены за один запуск;
- защита от «пинг-понга» (бесконечного поднятия цены при меняющемся соинвесте).
