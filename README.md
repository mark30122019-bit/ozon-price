# Ozon Price Adjuster

Автоматическая корректировка цен товаров на Ozon.

Скрипт проверяет, какую цену видит покупатель с Ozon Картой, и при необходимости поднимает вашу базовую цену в личном кабинете. Работает в Yandex Cloud и запускается по расписанию (например, раз в 10 минут).

---

## Что делает скрипт

1. Заходит в ваш магазин на Ozon через API.
2. Получает список всех ваших товаров и их текущие цены.
3. Смотрит цену для покупателя с Ozon Картой.
4. Если эта цена **ниже заданного порога** — поднимает вашу базовую цену так, чтобы витринная цена выросла на **5%** от текущей (настраивается).
5. Отправляет новые цены обратно на Ozon.

**Пример:** порог = **1500 ₽**, покупатель с картой видит **1200 ₽**, ваша база **1800 ₽**.  
Цель на сайте: 1200 + 5% = **1260 ₽** → базу поднимаем на **60 ₽** → новая база **1860 ₽**.

Если цена с картой уже выше порога — товар не трогается.

---

## Что нужно для работы

| Что | Где взять |
|-----|-----------|
| **Client-Id** | [seller.ozon.ru](https://seller.ozon.ru/) → Настройки → Seller API |
| **API-ключ** | Там же → создать ключ |
| **Аккаунт Yandex Cloud** | Для автоматического запуска по расписанию |

Скрипт работает **только с товарами вашего магазина** — те, что привязаны к вашим API-ключам.

## Настройки

| Параметр | Обязателен | По умолчанию | Описание |
|----------|------------|--------------|----------|
| `OZON_CLIENT_ID` | Да | — | Client-Id из личного кабинета Ozon |
| `OZON_API_KEY` | Да | — | API-ключ из личного кабинета Ozon |
| `TARGET_MARKET_PRICE` | Нет | `1500` | Порог: ниже этой цены с картой — товар корректируется (₽) |
| `SITE_PRICE_MARKUP_PERCENT` | Нет | `5` | Наценка к текущей цене на сайте при пересчёте (%) |
| `DRY_RUN` | Нет | выкл. | Если `1` — только показывает, что изменит, но **не меняет** цены |

**Где задавать настройки:**

| Где запускаете | Где хранятся секреты |
|----------------|----------------------|
| На компьютере | Файл `.env` (создаётся из `.env.example`) |
| В Yandex Cloud | Раздел «Переменные окружения» в настройках функции |

Файл `.env` **не загружается в облако** — в облаке ключи задаются отдельно в консоли Yandex Cloud.

## Деплой в Yandex Cloud через `deploy.zip`

В облако загружается **не весь проект**, а готовый архив **`deploy.zip`**.

### Что внутри архива

```
deploy.zip
├── index.py           ← точка входа для Yandex Cloud
├── requirements.txt   ← зависимости (requests)
└── app/               ← весь код приложения
    ├── config.py
    ├── env.py
    ├── pricing.py
    ├── ozon_client.py
    ├── prices_service.py
    └── pipeline.py
```

### Что в архив НЕ попадает (и не нужно загружать)

- `.env` — секреты задаются в консоли Yandex Cloud
- `tests/` — тесты только для разработки
- `run_local.py`, `pack.ps1`, `README.md` — только для работы на компьютере
- `.git/`, `deploy.zip` (сам архив)

### Шаг 1. Собрать `deploy.zip`

Откройте PowerShell в папке проекта и выполните:

```powershell
.\pack.ps1
```

В папке появится файл **`deploy.zip`** — его загружаете в Yandex Cloud.

Если `pack.ps1` не запускается, соберите архив вручную:

```powershell
Compress-Archive -Path index.py, app, requirements.txt -DestinationPath deploy.zip -Force
```

### Шаг 2. Создать функцию в Yandex Cloud

1. Откройте [Yandex Cloud Console](https://console.cloud.yandex.ru/) → **Cloud Functions**.
2. Нажмите **Создать функцию**.
3. Runtime: **Python 3.9** или новее.
4. Способ загрузки кода: **ZIP-архив** → выберите файл **`deploy.zip`**.
5. Точка входа: **`index.handler`**
6. В разделе **Переменные окружения** добавьте:

   | Имя | Значение |
   |-----|----------|
   | `OZON_CLIENT_ID` | ваш Client-Id |
   | `OZON_API_KEY` | ваш API-ключ |
   | `TARGET_MARKET_PRICE` | `1500` (или нужный порог) |
   | `SITE_PRICE_MARKUP_PERCENT` | `5` (или нужная наценка) |

7. Сохраните функцию.

> **Важно:** ключи Ozon вводятся в консоли Yandex Cloud, а не внутри zip-архива.

### Шаг 3. Настроить расписание (таймер)

Создайте **триггер-таймер** для функции:

| Интервал | Cron-выражение |
|----------|----------------|
| каждые 10 минут | `cron(*/10 * * * ? *)` |
| каждые 30 минут | `cron(*/30 * * * ? *)` |

Для небольшого каталога (4–10 товаров) оба варианта подходят.

### Шаг 4. Проверить логи

После первого запуска откройте **Cloud Logging** в Yandex Cloud.  
Там будет видно: сколько товаров найдено, какие цены пересчитаны, были ли ошибки.

### Как обновить код в облаке

После изменений в проекте:

```powershell
.\pack.ps1
```

Затем в Yandex Cloud → ваша функция → **Создать версию** → загрузить новый **`deploy.zip`**.

Переменные окружения при этом менять не нужно — они сохраняются в настройках функции.

## Проверка на компьютере (перед облаком)

Перед загрузкой `deploy.zip` в облако можно проверить работу локально.

### 1. Установить зависимости

```powershell
py -3 -m pip install -r requirements.txt
```

### 2. Создать файл с ключами

```powershell
copy .env.example .env
```

Откройте `.env` и впишите:

```
OZON_CLIENT_ID=ваш_client_id
OZON_API_KEY=ваш_api_key
TARGET_MARKET_PRICE=1500
SITE_PRICE_MARKUP_PERCENT=5
```

### 3. Безопасный прогон (ничего не меняет на Ozon)

В `.env` раскомментируйте:

```
DRY_RUN=1
```

Запустите:

```powershell
py -3 run_local.py
```

В консоли увидите, какие цены **были бы** изменены.

### 4. Реальный прогон

Уберите `DRY_RUN` из `.env` и снова:

```powershell
py -3 run_local.py
```

## Частые вопросы

**Как загрузить проект в Yandex Cloud?**  
Соберите `deploy.zip` командой `.\pack.ps1` и загрузите этот архив в Cloud Functions. Отдельные файлы загружать не нужно.

**Сколько товаров обрабатывается?**  
Все товары вашего магазина, привязанные к API-ключу.

**Как часто можно запускать?**  
Ozon ограничивает обновление цены одного товара — примерно **10 раз в час на каждый товар**. Запуск раз в 10–30 минут для небольшого каталога безопасен.

**Что если цена с Ozon Картой не приходит?**  
Такой товар пропускается, в лог пишется предупреждение.

**Где менять формулу расчёта?**  
В файле `app/pricing.py`. Подробнее — в [PRICING_AND_DISCOUNTS.md](PRICING_AND_DISCOUNTS.md).
